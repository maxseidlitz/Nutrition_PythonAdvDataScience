Section 10 · Supervised Learning Setup

Preprocessing for Machine Learning

Target: NOVA Group 1–4
Features: 12 (11 numeric + 1 categorical)
1

Feature & Target

What: We tell the model what to look at and what to predict. Inputs X = 9 nutrient values per 100 g + number of additives + number of ingredients + product category (12 columns total). Output y = the NOVA group (1–4) we want to predict.

2

Stratified Split

What: We randomly split products into a training set (80%, 18,724 products) to learn patterns and a test set (20%, 4,682 products) to check performance later. Why “stratified”: each NOVA class keeps the same share in both sets (e.g. group 4 ≈ 65%), so rare classes like group 2 are not lost in the test set.

3

Median Imputation

What: Many products have missing nutrient values (NaN). For each numeric column, we replace missing values with that column’s median from the training data only (SimpleImputer(strategy="median"). Why: most models cannot handle empty cells; the median is robust to extreme values (better than the mean for skewed nutrients).

4

StandardScaler

What: After filling gaps, we rescale every numeric feature so it has mean ≈ 0 and standard deviation ≈ 1 (StandardScaler). Why: energy is often hundreds of kcal, fiber only a few grams — without scaling, large-range features would dominate distance- or weight-based models unfairly.

5

One-Hot Encoding

What: Product category is text (e.g. beverages). We convert it into several 0/1 columns — one per category (OneHotEncoder). Why: models need numbers, not words. handle_unknown="ignore" means: if the test set has a new category, we don’t crash — that row simply gets zeros for all known category columns.

Pipeline Principle

  • ColumnTransformer: separate numeric & categorical branches
  • Fit only inside the model Pipeline on X_train
  • Test set gets transform only → no information leakage

Why Median?

  • Models need complete inputs
  • More robust than the mean for skewed nutrient values
  • Keep more rows instead of dropping them
